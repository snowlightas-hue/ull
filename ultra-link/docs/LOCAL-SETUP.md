# تشغيل ألترا لينك على حاسوبك

هذا الدليل يشغّل النسخة الكاملة على جهازك: الخادم، وقاعدة البيانات، والعامل الذي يبحث عن المطابقات في الخلفية.

على جهازك يعمل **الميكروفون** وتحديد **الموقع** في المتصفح. السبب أن المتصفحات تسمح بهما على `localhost`، أما صفحة التجربة المنشورة فلا تسمح بهما.

## 1) احصل على الكود
الكود على GitHub في المستودع `snowlightas-hue/ull`، الفرع `claude/wonderful-darwin-3nwr4x`، والمشروع داخل المجلد `ultra-link`.

```bash
git clone -b claude/wonderful-darwin-3nwr4x https://github.com/snowlightas-hue/ull.git
cd ull/ultra-link
```
بدون git: من صفحة الفرع على GitHub اختر **Code ← Download ZIP**، ثم فك الضغط وادخل المجلد `ultra-link`.

## 2) الطريقة الأسهل: Docker (ويندوز، ماك، لينكس)
1. ثبّت **Docker Desktop** وشغّله.
2. في مجلد `ultra-link` نفّذ:
   ```bash
   docker compose up -d --build
   ```
3. افتح **http://localhost:8080** في Chrome أو Edge، واختر شخصية تجريبية أو أنشئ حسابًا.

| ماذا تريد | الأمر |
|---|---|
| إيقاف | `docker compose down` (بياناتك تبقى) |
| تشغيل من جديد | `docker compose up -d` |
| تحديث لآخر نسخة | `git pull` ثم `docker compose up -d --build` |
| السجلات | `docker compose logs -f server worker` |
| مسح كل البيانات والبدء من الصفر | `docker compose down -v` |
| منفذ آخر إذا كان 8080 مشغولًا | ضع `UL_PORT=8081` في الملف `.env`، ثم افتح `http://localhost:8081` |

ما يحدث عند كل تشغيل:
- تُطبَّق تحديثات قاعدة البيانات وتُحدَّث التصنيفات.
- البيانات التجريبية المعلّمة «(تجريبي)» تُضاف مرة واحدة فقط عند أول تشغيل.
- الخدمة مفتوحة لهذا الحاسوب فقط (`127.0.0.1`).

## 3) إعدادات اختيارية: الملف `ultra-link/.env`
أنشئ الملف بنفسك. لا يُرفع إلى git ولا يدخل صورة Docker.
```
TYPESAFE_API_KEY=apikey_...                  # مفتاح Jev إن أردت تجربة الاتصال الحقيقي
UL_RECOVERY_PEPPER=<40 حرفًا عشوائيًا>        # لرموز استرجاع الحساب؛ لا تغيّره بعد أن تُنشئ حسابات
UL_DB_PASSWORD=<كلمة سر لقاعدة البيانات>       # اختياري؛ ضعه قبل أول تشغيل
```
- **`UL_RECOVERY_PEPPER`:** إن لم تضعه، يعمل التطبيق بقيمة تطوير ثابتة ويكتب تحذيرًا في السجل. هذا مقبول للتجربة الشخصية.
- **`UL_DB_PASSWORD`:** قاعدة البيانات غير مكشوفة خارج Docker أصلًا. إن غيّرت كلمة السر بعد أول تشغيل، احذف البيانات بـ `docker compose down -v`.

## 4) بدون Docker (لينكس، ماك، أو ويندوز عبر WSL2)
المتطلبات: Node 22.18 أو أحدث، وPostgreSQL 16 مع حزمة contrib.
- **لينكس:** `apt install postgresql-16 postgresql-contrib-16`
- **ماك:** `brew install postgresql@16`، ثم `export PGBIN="$(brew --prefix postgresql@16)/bin"`

```bash
npm install
npm start          # ينشئ قاعدة بيانات مستقلة في var/pgdata على المنفذ 5544، ويولّد كلمات السر في .env
# → http://127.0.0.1:8080
npm stop           # إيقاف الخادم والعامل
npm run status     # الحالة
```

## 5) الصوت والموقع
- **الصوت:** Chrome وEdge يدعمان التعرّف على الكلام بالعربية. اسمح بالميكروفون عندما يطلب المتصفح.
- **Firefox:** لا يدعم التعرّف على الكلام، والكتابة تعمل فيه.
- **الموقع:** زر «استخدم موقعي الحالي» يطلب الإذن من المتصفح. المتابعة المباشرة تعمل فقط والصفحة مفتوحة.
- **من الجوال:** المتصفحات تشترط HTTPS للميكروفون والموقع خارج `localhost`، لذلك يعمل الصوت حاليًا من نفس الحاسوب فقط. فتحه من الجوال يحتاج نشرًا مع شهادة HTTPS، وهذه خطوة لاحقة.

## 6) متابعة التطوير على حاسوبك مع Claude
جلسة Claude السحابية التي بنت المشروع لا تصل إلى حاسوبك. لتتابع العمل على جهازك:
- **إمّا** تطبيق **Claude Desktop**: افتح فيه مجلد `ull` وابدأ جلسة.
- **أو** في الطرفية داخل المجلد: `claude remote-control`، فتظهر الجلسة في تطبيق Claude Code.

ثم انسخ لها **البرومبت الجاهز** في آخر الملف `ultra-link/docs/HANDOFF.md`، فهو يشرح ما أُنجز وما التالي وبأي ترتيب.

بديل: أكمل العمل في الجلسة السحابية، ونفّذ أنت `git pull` ثم `docker compose up -d --build` لتجرّب آخر نسخة.
